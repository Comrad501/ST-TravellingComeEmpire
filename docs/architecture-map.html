STELLARIS 4.4.6 · PEGASUS · ARCHITECTURE MAP

Ark of Destruction

A travelling comet empire, and the six mechanisms it actually runs on

This maps the mod's subsystems onto the Clausewitz files that back them, so the dependency chains are visible before any of them are written. Two engine constraints force nearly every structural decision here; five unknowns are still open, and two of those block work that hasn't started yet. Everything below is drawn from the design notes — where the notes say unconfirmed, so does this page.

Base + Apocalypse + Federations + Nemesis Nomads — not owned, stubbed 1 blocking unknown v0.1 = AI crisis nothing blocks v0.1 40 raised · 6 open calibrated against a real save first live run done
§1

Two constraints shape everything else

Neither is a preference. Both are engine limits, and both are already confirmed in the notes. Almost every unusual choice further down exists to route around one of them.

CONSTRAINT A · MOVEMENT

Planets cannot be relocated

There is no mechanism to move a galactic_object. So the Ark never carries a planet — it carries a colony that has been detached from one. Pops, jobs, districts and name travel; the planet object stays where it was and becomes a husk.

CONSTRAINT B · SCOPE

Situations cannot target a fleet

A Situation lives on a country scope and its target is a planet or empire. The base-game README is explicit about the target modifiers:

"Does not work on other scope types!"

This is why the Planet Catcher is load-bearing, not thematic. A captured colony is the only thing on the Ark a Situation can legally hook into.

§2

The system, both sides of it

The mod is not one machine. It is an Ark-side machine and a defender-side machine that meet in a shared script layer — and the fight the design wants only exists because the two sides read and write the same handful of flags and counters. Every subsystem below is named by its backing directory, because that is where the coupling actually lives.

§3

How a world gets carried

The instinct is to move the planet. The engine has no way to do that, and building anything on the assumption that it might is the single most expensive mistake available here. The capture is two ordinary operations instead, each with vanilla precedent, and neither one moves a planet.

The consequence worth noticing early: a carried colony has a normal invasion surface. That is not a side effect to work around — it is the boarding stage of the kill sequence, free, using the planetary invasion system as shipped. Every world the Ark takes is another door into it.

§4

Containment, without a per-tick scan

The containment field inverts the usual fight: defenders don't need to win, they need to survive in place; the Ark doesn't need to win, it needs to thin the emitters below a threshold and jump. Field strength is a function of how many inhibitor ships are alive nearby, so the mechanic lives or dies on how that number is obtained.

Counting it by iterating the ship list is the pattern that produces late-game slowdown, and the notes already record a save with 6,000+ ships. The count has to be maintained, not measured.

§5

The kill is a sequence, not a health bar

A boss you out-build is the wrong shape, and vanilla already says so: the Contingency and the Blokkat-Vester are both flatly invulnerable until a specific non-combat objective is met. The Ark follows the same rule — three gates, each opened by something other than damage.

§6

The stub seam

Two mechanisms — attaching a colony to the Ark, and stripping the comet shell — both have a Nomads implementation and a base-game one, and the DLC isn't owned. Rather than pick now, callers bind to four fixed names and the backing sits behind them.

The cost is one layer of indirection. What it buys is that the decision can be made later, or reversed, without touching a single call site — and that the mod stays runnable on the install that actually exists today.

§8

Four ways this fails silently

Each of these is recorded in the notes as a known trap. None of them produce an obvious error — they produce a mod that loads and then quietly misbehaves, which is far more expensive to find.

STATE LOSS

Swapping the ship_size

Treating "shell up" and "shell down" as two hulls means transferring modules, tier, damage, leaders and every attached colony on each transition. Layer a particle effect over one persistent entity instead — the ship object is never destroyed.

STUCK FOREVER

Omitting destroy_situation

A situation that reaches on_progress_complete or on_fail without calling destroy_situation = this stays live permanently. Nothing warns you; it just never goes away.

HARD ERROR

Missing desc keys

Every modifier block inside a monthly_progress script value needs its own localisation key. Skip one and the game errors rather than degrading — cheap to fix, easy to forget while iterating.

NO SOUND, NO WARNING

Encoding on music files

Both the .asset and the .txt need UTF-8 with BOM, and the track must be .ogg. Wrong encoding fails silently. Note the ambient-overwrite route wants .wav instead — a different pipeline entirely.

One more that isn't a trap so much as a prerequisite: EFCF is already installed, so this is a multi-mod setup. The DEBCF wiki's page on overwriting specific elements is worth reading before the first file is written, not after the first conflict.

§9

Build order

Sequenced so the two blocking unknowns are hit as late as possible, and so nothing gets built on top of an assumption that might not survive a prototype. Steps 1–6 need no unknown resolved.

  1. Mod skeleton

    descriptor.mod, directory tree, localisation stub, .gitignore. Loads and does nothing — which is the point.

  2. Ark hull and comet shell

    The ship_size, and the shell as a high-HP, high-regen defensive layer with an upkeep cost. Spawnable and lookable-at. No state swapping.

  3. Stub seam, empty

    The four names from §6 defined with correct signatures and no bodies. Locks the interface before anything calls it, so U4 and U5 stay genuinely deferred.

  4. Containment counting

    Tag-on-construction, three on_action hooks, one cached variable, one shared scripted_trigger. Performance-critical, so it goes in early and correct rather than late and retrofitted.

  5. Planet capture — Backing B

    Colossus-style strip plus colony transplant, behind ark_attach_colony. Produces a real carried colony, which unblocks both the situation layer and boarding.

  6. Situation layer

    Targeted at a carried colony per Constraint B. Bidirectional progress bar: contained at one end, escaped at the other. Fleet-level behaviour stays in fleet_event.

  7. Planet Catcher rendering

    Prototype U1 first. If sections can't swap live, fall back to a single mesh with all four cradles modelled and per-cradle visibility flags — uglier, certain to work, and it does not change anything above the seam.

    GATED ON U1 · U2

  8. Kill sequence

    Stages 2 and 3 can be built now — boarding is vanilla, and the Golem is a species-targeted one-use weapon. Stage 1 waits on your call about what replaces the Nomads cannon.

    GATED ON U5

  9. Music

    Playlist entry costs almost nothing and can ship whenever. The stage-triggered cue depends on U3 and is explicitly not worth blocking on.

§10

What the notes don't cover at all

Distinct from U1–U5. Those are questions the notes ask and can't yet answer; these are areas the notes never reach. Tier 1 changes what gets built, so it can't be deferred the way the unknowns can.

TIER 1

Architectural — answering these changes the build

4 gaps
G1

Is the Ark a crisis, a playable empire, or both?

The notes read both ways and never settle it. "Houses the empire's seat of government" and the player-side overload component point at playable. "Gives the defending side a real mid-game objective", "the Ark will prioritize killing it", and the Contingency/Blokkat framing point at an AI crisis.

This is the gap that sizes every other one. A crisis needs spawn conditions and AI behaviour and no economy at all; a playable empire needs an origin, a tech path, a build loop, and the whole of G2. They are not the same mod.

G2

The economy of an empire with no homeworld

One parenthetical about energy upkeep is the entire coverage. Unanswered: where income comes from; whether carried colonies run normal districts, buildings and jobs; whether the Ark acts as a mobile shipyard and starbase; what replaces the capital building chain, which requires a capital planet; how sprawl and admin cap work when you own no systems.

If G1 resolves to playable, this is roughly the larger half of the mod and it is currently unwritten. If it resolves to crisis, most of it evaporates.

G3

What happens when the Ark dies

If the seat of government is aboard, does the empire end instantly? What becomes of the four carried colonies — re-shattered, released as independents, or deleted with their pops? What if it dies while a situation is mid-progress and its target colony went down with the ship?

Partly a design question, partly a stuck-state risk: the situation layer's destroy_situation requirement needs someone to call it, and the obvious caller is the thing that just stopped existing.

G4

How the defender learns the kill sequence

There is a staged kill and a losing condition, but no event chain, research path, or advisor prompt that teaches anyone the cannon is the answer.

A stage-gated boss that never reveals the gate is indistinguishable from an unkillable one. The losing condition fires and the player never knew a counter existed. Vanilla teaches both the Contingency and Blokkat counters explicitly.

TIER 2

Specified too loosely to implement

4 gaps
G5

Nothing anywhere is quantified

No shell HP or regen rate. No containment radius R or ship-count threshold N. No duration for the exposed window after a shell strip, no capture duration, no Ark fleet power relative to a mid-game empire, no count of worlds at which the crisis is considered won.

Placeholder numbers would be enough. Without any, the design is describable but not testable — there is nothing to be right or wrong about yet.

G6

The Golem is one sentence

"Kills a target empire's population outright" leaves the scope open: all pops of a species galaxy-wide, one planet, or one empire's worlds? "Seized from the throne room" leaves the mechanism and the interface open too.

It is the reward for the entire boarding stage, so its scope sets how valuable stage 2 feels.

G7

The Anti Wave Motion Lattice is orphaned

Named once, flagged as needing a new component from scratch, then absent — not in the kill sequence, not in containment, not in the open questions.

Needs an explicit in-scope or cut. Right now it is neither, which is the state that quietly costs time later.

G8

AI behaviour, if G1 resolves to crisis

Zero coverage. When does the Ark jump, how does it choose targets, does it prefer weak empires or rich ones, how does it escalate over a campaign, how does it respond to difficulty and galaxy size?

The containment mechanic only produces interesting play if the Ark's side of it is making decisions worth countering.

TIER 3

Process — not design, but it will cost time

4 gaps
G9

Compatibility with EFCF

EFCF is installed and the notes already cite it as the working reference for locators — which means it touches the same file categories this mod will. There is no audit of whether they collide on ship_sizes, section_templates, or on_actions, and load order gets a single mention.

G10

The development and test loop

Nothing on how iteration actually happens: where error.log lives, the console commands to spawn the Ark, debugtooltip, a prepared test save.

This is the gap that gates the others. U1 and U2 can only be resolved by running the game, and I cannot run it — so the speed of your test loop is the speed of the whole project.

G11

No definition of done

No split between a first release and a complete one. With two blocking unknowns and a possibly-large economy subsystem, a deliberately small v0.1 is worth defining now.

G12

Save-game and version durability

No position on whether saves survive a mod update, what happens to an in-flight Ark when Stellaris patches, or whether the mod is ironman and achievement compatible.

WORTH DECIDING EARLY, NOT LATE

Intellectual property, if this ever goes to the Workshop

The concept is closely derived from Space Battleship Yamato — Gatlantis, Zemuria, the Archelias, the Ark of Destruction, wave motion technology. For a mod you run locally this is a non-issue. For a public Steam Workshop release it is real exposure: anime rightsholders do issue Workshop takedowns, and the risk is considerably higher if models, textures, or music are extracted from the games rather than made from scratch.

Raising it now because it is a decision about where the art comes from, and that gets expensive to reverse once assets are made. Original assets in the same visual language carry far less risk than ripped ones. This is your call to make — it just costs less to make it before the pipeline in §8 of the notes gets built out.

§11

G1, decided: an AI crisis first

DECISION · SUPERSEDES G1

v0.1 ships the Ark as an AI crisis. Playable is deferred, not dropped.

A playable displaced empire is the more interesting version and stays on the roadmap — but it is the harder build, and it is the one that most needs playtesting to justify. Crisis first means the mechanics get tested before the scope gets spent on them.

The saving is real but uneven. This is what actually moves:

LARGELY DEFERRED

G2 · the economy

Crises conventionally sidestep an economy: fleets arrive by event rather than being built, so no income model, no capital chain, no build UI. The largest gap in the list mostly stops mattering — for now.

PROMOTED TO CRITICAL

G8 · AI behaviour

It was the gap you could ignore while G1 was open. It is now the whole opposing player. Target selection, jump timing, escalation, scaling — and it still has zero coverage in the notes.

NOW MANDATORY

G4 · teaching the counter

Against an AI crisis the player is purely on the receiving end and has no other route to the rules. Without a reveal chain the kill sequence is unreachable by design.

UNCHANGED

Build steps 1–6

Hull, shell, stub seam, containment, capture, situation layer. All sit in the shared core, so none of them are wasted if the playable branch is built later.

The race the crisis actually is

A crisis is a pacing problem before it is a combat problem: the Ark collects on one clock and the defenders arm on another. Everything the AI layer has to decide is a question about where on this line something happens.

What choosing crisis newly opens

G13

Four slots, or indefinite collection?

§1 caps the Planet Catcher at roughly four worlds. §4 defines the losing condition as the Ark "collecting worlds indefinitely". Under a crisis reading these cannot both hold: a four-slot cage has a natural stopping point and therefore no escalation.

Four shapes to pick from: slots free as worlds are drained; four is only what renders while the tally is unbounded; the loss condition is time-based rather than count-based; or the Ark shatters worlds it cannot carry. Each implies a different escalation curve, so this is upstream of every number in G5.

G14

Spawn trigger and timing

Endgame-year like the vanilla crises, or mid-game? The notes want the cannon to be a mid-game objective, which pulls the Ark's arrival earlier than a standard crisis and lengthens the campaign it occupies.

Also unanswered: where it enters, whether the galaxy gets warning, and whether difficulty or galaxy size move the date.

G15

Target selection and jump policy

Which worlds does it want — highest pop, nearest, weakest defender, best deposits? And when does it choose to leave a system: on containment breaking, on a timer, on damage taken, on having filled a slot?

Jump policy is where containment either becomes interesting or becomes noise. If the Ark leaves the moment containment weakens, holding it is meaningful; if it leaves on a timer, the inhibitor ships are decoration.

G16

Escorts and reinforcement

Does the Ark travel alone or with a fleet, and if so, where do replacements come from? Crises conventionally spawn reinforcements by event on a schedule rather than building them, which keeps G2 deferred — but that schedule is itself an escalation curve nobody has drawn.

None of these block build steps 1–6, which is the point of having sequenced it that way. They block step 8 and the tuning pass, and G13 in particular is worth answering before any number in G5 gets picked, because it decides what those numbers are measuring.

§12

Worthiness: which worlds are taken, and which are broken

The Planet Catcher stops being indiscriminate. Every candidate world is scored, and the score produces one of three verdicts — not two. That third verdict is what makes the crisis's escalation coherent.

RESOLVES G13

A shattered world costs no slot, so the cage can hold four forever

The contradiction was that a four-slot cap gives the Ark a natural stopping point, leaving nothing to escalate toward and therefore nothing to lose to. Worthiness dissolves it: worlds that fail assessment are destroyed rather than carried, consuming nothing. The Ark advances through the galaxy indefinitely while never holding more than four. Both halves of the notes hold at once.

Two tiers, because "which empire" and "which world" are different questions

Empire-level score decides who the Ark preys on. Planet-level score decides which of their worlds it wants. Keeping them separate matters: a strong empire's worst colony shouldn't automatically outrank a weak empire's crown jewel, and collapsing both into one number makes that impossible to express.

The fork you named, and why it isn't a free choice

You offered two bases for worthiness. They are not interchangeable — they produce opposite incentives in the case that matters most, which is a weak empire that fights hard.

OPTION A

Strength · the Ark covets the impressive

Worthiness tracks how formidable an empire is. The galaxy leader becomes the target, which gives the crisis a natural antagonist and puts pressure where the resources to answer it already are.

Deterministic. The Ark beelines the leader every campaign, so the mechanic stops being a decision after the first playthrough — and a runaway player is punished for playing well, which some will read as arbitrary.

OPTION B

Damage · the Ark respects what hurt it

Worthiness tracks what an empire has cost the Ark. Far more dramatic: the empire that resists earns its own destruction, which fits the source material's logic much better than a pure power ranking does.

Alone, it rewards turtling. If the only consequence of fighting is becoming the target, the correct play is to let your neighbours die — which directly undermines G4, the whole point of which is getting players to engage the kill sequence.

OPTION C · RECOMMENDED

Strength sets the floor, damage escalates it

Empire strength establishes a baseline ranking, and damage dealt acts as a multiplier on top. A strong quiet empire is a standing target; a weak defiant one climbs the list fast. Both of your instincts survive, and neither dominates.

Still needs an offsetting reward for being marked, or B's turtling incentive returns in weaker form. Worth pairing with something the player gains — warning time, intel, or a route to the Golem.

DECISION · SCORING BASIS

Option C. Strength sets the floor, damage escalates it.

Which leaves the offsetting reward still owed. Without it, Option B's turtling incentive survives in weaker form — and that debt is paid in §13, where the same worthiness verdicts turn out to be the lever that fixes it.

Implementation shape

The same rule from §4 applies and for the same reason: worthiness is maintained, not measured. A score recomputed by walking empires and their planets on a timer is the 6,000-ship problem wearing a different hat. Damage dealt in particular has no native tracker, so it becomes a country-scoped counter incremented from on_actions — Ark ships destroyed, hull damage taken, the cannon completed — and read, never totalled.

That keeps the whole thing inside the shared script layer already drawn in §2: one script_value for the score, one scripted_trigger for the verdict, and the same caching discipline as the containment count.

G17

Which empire-strength comparator, and does it exist in script?

"Victory points" is the right instinct, but the exact scriptable handle needs confirming against the installed version — relative power ratings, victory score, fleet power, or a composite the mod computes itself.

I cannot verify this from here. It is a fast check in the game files, and it decides whether Option A and C are implementable as written or need a hand-rolled substitute.

G18

Damage dealt has no native tracker

Nothing in the base game records what a given empire has cost a given fleet. Option B and C both require the mod to maintain that counter itself: which events increment it, by how much, and whether it decays over time so an old grudge fades.

Decay is not a detail. Without it, an empire that fought the Ark in 2300 is still top of the list in 2400, and the mechanic stops responding to anything the player does.

G19

Can the player see their own worthiness?

A hidden score that decides which of your worlds gets eaten is indistinguishable from arbitrary AI behaviour. If it is visible — as an opinion-style readout, a situation stage, or an event when you cross a threshold — it becomes a dial the player can act on.

This is G4 again in a different costume. The mechanic only produces decisions if the player knows it exists.

One consequence worth stating plainly: DISPLACE means a world the Ark already carries can be jettisoned. That is a live question for §10's G3 — whatever happens to carried colonies when the Ark dies is now also what happens when one is evicted, so the two want a single answer.

§13

Fighting before it is your turn

A crisis everyone agrees is fatal, and that nobody moves against until it reaches their own border, is not a coordination failure in the players — it is a payoff table the design handed them. Free-riding is the correct play unless the mechanics make it wrong.

The lore does real work here, but not the work it looks like. "All biological and emotional life ends" establishes that there is no survivable neutral position — but stating that in an event popup changes nothing, because a player who has read the tooltip and a player who has not will both still calculate that the empire two jumps away is a cheaper shield than their own fleet. Inevitability has to be demonstrated and enforced, not asserted.

L1 · THE LEVER YOU ALREADY BUILT

Invert what the verdicts mean for the victim, and turtling stops being safe

Under Option C, an empire that never fights never accrues damage, so its worthiness stays low — and low worthiness means SHATTER, not ASSIMILATE. Read from the victim's side that reverses: an assimilated world keeps its pops alive aboard the Ark, and a carried world is recoverable by boarding in stage 2. A shattered world is gone permanently, with everyone on it.

So the empires that fought have their losses held in escrow, and the empires that abstained are simply erased. The free rider does not merely fail to gain — it draws the worse of the two fates. And it is exactly what the lore already says: the Ark is not angry with you, it is deciding whether you were worth continuing.

That single reframe pays off the debt left by Option C in §12. It costs no new systems: the score, the verdicts and the boarding surface all exist already. What it costs is communication — a player who assumes being captured is the worse outcome will read the whole mechanic backwards, so this is the thing the reveal chain in G4 has to teach first.

The other four

L2

Make the ledger public

G19 stops being a UX nicety and becomes the coordination substrate. If every empire can see the worthiness standings and the Ark's distance from its threshold, doom stops being abstract and becomes a schedule. Pair it with a galaxy-wide broadcast the first time a neutral empire is shattered: observed precedent teaches inevitability in a way no tooltip manages, and it teaches it while there is still time to act on it.

L3

Put the containment floor above any single empire

Straight from §5: containment holds while N inhibitor ships survive within radius R. Tune N above what one empire can plausibly field mid-game, and pinning the Ark becomes a physical coalition act rather than a moral one.

The strongest of the five, because it is a constraint rather than an incentive — it does not care whether anyone wanted to cooperate. It also finally gives the Ark's spinal AoE weapon its purpose: it exists to break coalitions, not to kill single ships.

L4

Fund the cannon jointly

Federations is owned, so the Galactic Community is available. Make the shell-stripping cannon a community project with pooled cost, or price it beyond any one mid-game economy. Cooperation then becomes structural — nobody has to be persuaded, because nobody can afford it alone.

This also gives U5 its shape. Whatever substitutes for the Nomads Stellar Cannon should be designed as a shared build from the start, rather than a private one that gets a cooperation mechanic bolted on later.

L5

Make the Golem a prize, not a commons

Track per-empire contribution and award the Golem to whoever contributed most. A reward that cannot be split converts a collective action problem into a competitive one: the race becomes who can help the most rather than who can abstain longest.

Cheap relative to its effect, and it uses G6's unresolved scope productively — the Golem needed a defined owner and a defined reach anyway.

THE LOAD-BEARING CAVEAT

Four of these five assume the other empires respond to incentives

In single-player the coalition is mostly AI, and Stellaris AI does not reliably coordinate against crises even when the incentive is plain. A design that depends on emergent AI cooperation will read to the player as a broken promise: the mechanics say band together, and then nobody comes.

So the cooperative outcome has to be reachable without the AI choosing it — the Community resolution passing on a scripted threshold rather than on votes, or L3's N being meetable by one player plus scripted allies. L3 survives this caveat because it is a constraint; L1 survives because it punishes the abstainer directly rather than rewarding a coalition. The other two need scripting to be dependable.

G20

Is cooperation required, or merely rewarded?

L3 makes it a hard gate; L1, L4 and L5 make it strongly advantageous. These are different games. A hard gate guarantees the intended shape but removes the choice, and a crisis you cannot attempt alone will read as scripted to some players.

Worth deciding as a stance rather than emerging from tuning, because it sets what every number in G5 is aiming at.

G21

AI cooperation cannot be assumed

How much of the coalition is scripted versus emergent, and what the player sees if the AI fails to show up. Needs a floor: the minimum guaranteed help, and where it comes from.

G22

Contribution tracking

L5 needs a per-empire contribution counter, and it is the same shape as everything else here — incremented from on_actions, cached, never totalled by scanning. It can likely share plumbing with G18's damage counter, since both are measuring the same events from opposite sides.

§14

The reward is the shot itself

DECISION · SUPERSEDES G20

Cooperation is rewarded, not gated. What it buys is cannon yield.

No hard threshold, no "you may not attempt this alone". Contribution converts into how hard the shell-stripping shot lands — and because §4 already establishes that conventional fire cannot touch the shell, cannon yield is the only thing "more firepower to shed it" can mean. The two halves of the design were already pointing at each other.

This reward has a property worth naming, because it is the reason it works where a generic one would not: it is only spendable on the Ark. Fleet capacity, research bonuses or resource grants can all be banked and turned into winning the campaign some other way, which makes helping just another investment to compare against expansion. Yield against a shell that exists for one purpose cannot leak out of the crisis. You either spend it on the Ark or you never spend it.

The chain, and where a thin coalition actually breaks

Yield does not kill anything by itself. It sets how long the shell stays down, and the window is what stage 2 spends: ground armies need time to land and fight inward. So a weak shot does not fail at stage 1 — it fails at stage 2, halfway through a boarding action, when the shell comes back with your armies aboard.

A CONSTRAINT THAT DOES NOT FEEL LIKE ONE

The per-empire cap delivers L3's guarantee without L3's hard gate

A solo empire is never told no. It builds the cannon, it fires, the shell drops — for about two years, which is not enough to finish a boarding action. It fails at a step it could see coming, for a reason it can name, and the fix is obvious and available: bring more people.

That is a far better failure than a threshold refusing the attempt. The coalition requirement is still there, mathematically, but the player discovers it by playing rather than by reading an error message.

Two things this changes upstream

L3 should soften to match. A hard containment floor now contradicts the stance: if the cannon degrades gracefully for a thin coalition, containment should too. §5 already wants this — containment strength as a function of live inhibitor count degrades on its own, so the fix is to leave it degrading rather than adding a minimum.

L5 needs two readings of one counter. Awarding the Golem to the largest contributor stops discriminating if everyone caps out. So the contribution counter is read twice: capped when it feeds cannon yield, raw when it ranks empires for the prize. One counter, two consumers — the same pattern as the containment trigger in §4.

G23

The yield curve and the cap value

What one empire's maximum share is worth, and how segments combine. Straight summation is simplest; a curve with diminishing returns past some contributor count stops a twelve-empire galaxy trivialising the shot.

Also unsettled: whether yield sets window length only, or also how much shell comes off, and whether a partial strip leaves the Ark partly vulnerable rather than being binary.

G24

What counts as contributing

Damage dealt and resources committed to the cannon are obvious. Inhibitor ships held in containment should probably count, since that is the other thing the design wants people doing. Whether suffering counts — worlds lost to the Ark — is a genuine choice: it is a catch-up mechanic for empires hit early, but it pays out for being a victim rather than a participant.

G25

Who fires it, and is a wasted shot recoverable?

If the cannon is a shared build with any owner able to fire, one impatient empire can discharge it at 18% and spend the coalition's whole investment. If it is single-use, that is unrecoverable and the crisis is decided by the least patient participant.

The sharpest of the three. A recharge period is the obvious answer — long enough that a premature shot hurts, short enough that it is not campaign-ending — but the firing authority still needs an owner, and in a Galactic Community build that is a political question the game already has machinery for.

§15

No cannon. Just guns, and enough of them.

DECISION · REPLACES THE STAGE 1 GATE

The shell is stripped by fleet fire, not by a unique megastructure.

Players need firepower, not a building. Which means stage 1 stops being a construction project with a trigger on it and becomes what it should probably always have been: a fight you have to win hard enough, for long enough.

This deletes more than it adds. Three open items close outright, one of them the second of the two blocking unknowns:

DISSOLVED

U5 · the Nomads cannon

Stage 1 was built on a Stellar Cannon from a DLC that is not owned. With no cannon there is no dependency and nothing to substitute. The blocking unknown does not get answered — it stops existing.

DISSOLVED

G25 · who fires it

No single trigger means no firing authority, no premature discharge wasting a coalition's investment, and no recharge rule to design. Everyone shooting is everyone participating.

SUBSUMED

L4 · joint funding

The Galactic Community build existed to make cooperation structural. Damage is already additive across empires, so the coalition mechanic is now native to the combat instead of bolted onto a shared construction.

HALVED

The stub seam

ark_shell_strip and ark_shell_strip_ready had two possible backings only because of the cannon. Shell stripping is now plain base-game combat maths, so only the colony-attach half of the seam still needs to swap.

The premise has to invert, and it inverts into something better

§4 said conventional fire cannot touch the shell, which is what the cannon existed to solve. Dropping the cannon means dropping that too — so the question stops being "can you damage it" and becomes "can you out-damage its regeneration". That is a rate problem, not a total. It has a threshold, and thresholds are what make coalitions matter.

Model the shell as regenerating in proportion to how damaged it is, the way a shield does. Then incoming fire and regeneration find an equilibrium, and where that equilibrium sits decides everything:

The window stops being a timer

Under the cannon, yield bought a fixed countdown. Under sustained fire it buys nothing of the sort: the shell stays down for exactly as long as you keep out-damaging it. Break off, lose the line, or get thinned below the threshold and regeneration restarts immediately.

That collapses three things the design had been treating as sequential into one engagement.

What stops one superpower doing it alone

§14 used a per-empire cap for this. Raw damage cannot be capped without it feeling arbitrary, so the honest answer is to move the threshold instead: scale regeneration with the number of worlds the Ark has collected.

Early, a single strong empire genuinely can out-damage it — and that should be allowed, because acting early at real cost is exactly the behaviour the whole of §13 was trying to buy. Late, after the Ark has fed, no one fleet is enough. The gate becomes time rather than permission, which is what "rewarded, not gated" ought to mean, and the Ark's own growth becomes the difficulty curve rather than a separate tuning knob.

WHAT THIS COSTS

The defenders lose their concrete mid-game objective

The cannon was a thing to build and protect — something specific to do between attacks. "Assemble a large fleet" is not a replacement, because that is what every Stellaris campaign is already doing anyway. Without something in its place, the mid-game loses a beat.

The version that fits "players need firepower, not a building" is a researchable anti-shell weapon component: a real progression objective with a tech path behind it, fitted to any ship by any empire, with no single point of failure and nothing to capture. It preserves the sense of preparing a counter while keeping the counter distributed.

G26

Is the shell a flat damage check, or does it discriminate?

If any damage counts equally, stage 1 is a pure fleet-power stat check and composition stops mattering. Resistances by weapon class, or a rule that only sustained fire counts while alpha-strike does not, would give the fight texture — at the cost of a fleet-building puzzle players have to be taught.

G27

What the mid-game objective becomes

Whether the anti-shell component above is the answer, and if so where it sits: a normal tech, a rare tech, or something recovered from a shattered world — which would tie it back to the reveal chain in G4 and give the Ark's own destruction the job of teaching its counter.

§16

Tech: what the engine will actually give us

CONSTRAINT C · THE THIRD ONE

Stellaris has no browsable tech tree, so a "tech tree" is not the thing to build

Research is a card draw. Each area — Physics, Society, Engineering — offers three alternatives at a time, selected by weight from everything currently valid. There is no screen where a player traces a path from the comet to its counter, because no such screen exists for anything.

Worse for our purposes: a technology that appeared in the previous hand has its weight halved in the next draw. Anything left to weight alone can hide for years. Prerequisite chains are real and scriptable; the tree that would let someone see the chain is not.

So the answer to "can we gate a tech tree on the comet event" splits in two. The gating: yes, cleanly. potential = { has_country_flag = ark_revealed } decides whether a country may draw a technology at all, so the whole branch simply does not exist in anyone's pool until the Ark shows up — which also means it never dilutes the early game. The tree: no, and designing as though players can see one is the trap.

That matters most because of a hazard the card system creates for crisis content: anything mandatory must not be random. If the counter to the Ark sits behind a weighted draw, some campaigns lock the player out by luck. The structure below keeps the required path deterministic and lets only the optional depth ride the draw.

The three mechanisms, and what each is actually for

01

Special projects — the mandatory spine

Defined in common/special_projects/, started from an event with enable_special_project (name, location, owner) and cancellable with abort_special_project. Once enabled they simply exist: assign a scientist, it completes. No draw, no luck.

This is where the reveal chain from G4 belongs. Anything a player must learn to beat the Ark goes here, because it is the only research-shaped mechanism that cannot be missed.

02

Technologies — optional depth, gated so they never clutter

potential = { } decides whether a country may draw a tech at all, so has_country_flag = ark_revealed keeps the entire branch out of the pool until the crisis exists. weight_modifier then biases the draw, and add_research_option from a completing project can put a specific card in the player's hand outright when determinism is needed.

Use is_rare for the branch if it should feel like a find rather than a routine unlock; use give_technology only where a tech should be a reward rather than a research decision.

03

Repeatable techs — where "more firepower" actually lives

§15 made the crisis a rate problem: your contribution is damage per unit time against a regenerating shell. A repeatable anti-shell tech is the natural expression of that — an empire can keep investing to raise its own share of the threshold, with no ceiling and no building to protect.

It also gives a late-joining empire a way to catch up and matter, which the coalition design in §13 wants.

G28

Will the AI research any of this?

Gated techs need weights and ai_update_type set so AI empires actually take them. If they do not, the AI turns up to the fight with no anti-shell weapons and contributes nothing to the threshold.

This compounds G21 rather than sitting beside it. "The AI will not cooperate" becomes "the AI cannot cooperate, because it never researched the thing that would let it" — a much harder failure to paper over.

G29

Two curves that race

Repeatable anti-shell research raises coalition damage over time. Shell regeneration scales with worlds collected, also over time. Those are two growth curves pointed at each other, and which one wins decides whether the crisis is beatable, trivial, or hopeless.

Probably the single most important balance relationship in the design, and it cannot be tuned until G5 has numbers at all.

Verified against community documentation this session, not against the installed game: technology fields and the card-draw behaviour, the special-project effects, and create_archaeological_site. Version-specific details for 4.4.6 still want a check against the local files before anything is written.

§17

Taking the Ark: a precursor route for machine empires

CORRECTION TO §16

The dig site survives, but its reward cannot be minor artifacts

§16 hung the third research branch on an archaeology site without checking its DLC footprint — the same mistake U5 was. Checked now: sites can be created and excavated without Ancient Relics, but minor artifacts require it, and Ancient Relics is not owned. So the mechanism holds and the chapter rewards have to be ordinary ones — a tech option, a modifier, an event — never artifacts or relics.

PROPOSAL · v0.2 BRANCH

Acquisition is not displacement, and that is what makes it affordable

§10's playable branch assumed an empire with no homeworld, which dragged an entire economy behind it. A precursor chain that hands the Ark to an existing empire is a different proposition: the player keeps their worlds, their economy and their capital, and gains a mobile fortress. Most of what made the playable branch expensive simply does not arise.

And the galaxy's response to a player holding the Ark does not need writing either. Nemesis is owned, and its Become the Crisis path already implements exactly that situation: a Menace resource earned through destruction, crisis levels each gated behind a special project, crisis perks that unlock new ship types, and a permanent opinion penalty with every empire in the game. The coalition machinery in §13 was designed against an AI Ark; pointed at a player, vanilla already runs it.

The chain is a race, and the deadline already exists

The strongest version makes the precursor chain compete directly with the crisis timer. Finish before the Ark would have woken on its own and it is yours. Fail, and it wakes anyway — and the empire that spent a century hunting it is the one that knows exactly what is coming. G14's spawn date stops being a tuning value and becomes the clock the whole branch is played against.

What this actually costs, against §10's version

The playable branch in §10 needed five subsystems. Three of them stop existing under acquisition, and one is supplied by a DLC already owned.

Subsystem§10 displaced-empire branchPrecursor acquisition

Why machine empires specifically

Beyond the fiction, the restriction does real work. It bounds the balance surface to one empire type instead of all of them; Nemesis already excludes xenophile, pacifist and rogue servitor empires from the crisis path, so most machine empires are eligible without fighting the existing rules; and a machine empire's assimilation of populations rhymes with the Planet Catcher's ASSIMILATE verdict closely enough that the two can share vocabulary rather than competing for it.

The verdicts from §12 also stop being AI policy and become player decisions. Choosing which worlds are worth carrying and which are only worth breaking is a considerably more interesting thing to hand a player than a damage number — and it is already specified.

G30

Does the player keep their capital, or give it up?

Keeping it is what makes this cheap, and makes the Ark a fortress rather than an identity. Giving it up is closer to the source material and to the original "displaced empire" idea — and brings G2's entire economy problem back with it.

This is the fork that decides whether the branch stays a v0.2 addition or becomes the large build again. Worth answering before any of it is written.

G31

Can a player Ark and an AI Ark coexist?

Mutually exclusive is cleaner and gives the race its stakes. Allowing both is more dramatic and doubles every balance question, since the galaxy would then face two comet empires with no guarantee they fight each other.

§18

One Ark, already buried

DECISION · SUPERSEDES G31

There is exactly one Ark. It is in the galaxy from the first day, asleep.

Not two systems that happen to be mutually exclusive — one unique object, placed at galaxy generation and dormant, that either gets dug up or wakes on its own. Which reframes the whole thing: the Ark is not spawned by a crisis system on a schedule. It is already there, and the crisis is simply what happens if nobody reaches it first.

LORE CORRECTION

The Archelias built it. Zemuria is something it takes.

The precursor civilisation is the Archelias; Zemuria stays what the notes always had it as — one of the worlds the Planet Catcher captures. So the chain is not an empire recovering its own ancestors' weapon. It is an empire finding somebody else's, understanding it imperfectly, and using it anyway.

That is a better fiction for the same mechanics, and it makes the machine-empire restriction easier to justify in-world rather than as a balance gate — if the Archelias were themselves synthetic, only a machine intelligence can interface with what they left behind. Flagging that last part as my proposal, not your lore: say if the Archelias were organic and I will find the restriction a different reason.

What "already buried" buys, mechanically

A dormant object costs nothing. Galaxy generation flags one system as the cradle and spawns no fleet at all — no entity to path, no AI to run, no contribution to the ship counts that §4 spent so much care avoiding. The Ark is a flag and a location for most of a campaign, and only becomes an object at the moment something wakes it.

It also gives the precursor chain something real to point at. The final clue does not conjure a destination; it names a system that has been sitting there, surveyable, since turn one.

G32

How early is too early?

A lucky survey run could put the chain's first clue in a player's hands within a few decades. If the chain can then be finished by year 60, one empire holds a galaxy-ending fortress before anyone has the fleets or the research to answer it.

§15 already softens this — regeneration scales with collected worlds, so a freshly woken Ark is at its weakest — but that governs how hard it is to kill, not how hard it is to survive. The chain probably needs a floor: a minimum date, a prerequisite tech, or clue sites that only become surveyable after some point.

G33

Should an AI empire be able to win the race?

It is the richest version — a real empire with a homeworld, diplomacy and grudges holding the Ark is a far more interesting crisis than an unowned fortress on a timer. It also inherits every problem in G21 and G28 at once, since the AI would need to pursue a precursor chain and operate the Ark competently.

Recommend leaving it out of v0.2 and keeping the third path drawn but dark. It is the obvious v0.3, and designing the other two so they do not preclude it costs nothing now.

§19

Why the Ark tolerates machines

MY PROPOSAL WAS WRONG

The Archelias were humanoid, so "only a machine can interface with it" does not hold

I offered synthetic builders as the in-world reason for the machine-empire restriction. Zworder's account rules that out: the Archelias were humanoid, and it was precisely their humanoid form — carrying an intrinsic tendency toward violence and chaos — that he blames for their disappearance. They then created humanity in that same form, which is the part he cannot make sense of.

The lore gives a much better reason than the one I invented, and it reframes the Ark's purpose rather than just its access rules. If its builders concluded that humanoid life is intrinsically self-destructive, then the Ark is not a conquest engine at all. It is a correction — built to finish what the Archelias started and could not bring themselves to complete, by ending the flawed legacy they left behind. Which is exactly the framing you gave earlier: the end of all emotional and biological beings, not as cruelty but as remedy.

A machine empire is not that legacy. It is not what the Ark was built to judge — so it is not evaluated, and it can approach.

The consequence is sharper than the permission

Being outside the judgment is not the same as being safe. §12's verdicts exist to decide which of the legacy is worth carrying forward; a machine empire is not a candidate for that question at all. So it can never be ASSIMILATEd — there is nothing in it the Ark wants to preserve.

It also gives §16's dig site its narrative payload. Zworder's question — why would they rebuild the very form that destroyed them — is precisely the thing an excavation should surface, chapter by chapter, to an empire that is not humanoid and has no stake in the answer.

But holding it is not starting it

The Ark can only be activated by a human. A machine empire can reach it, own it and survive owning it — and still cannot switch it on.

Which is the sharpest thing in the whole design, because it is not a restriction bolted on for balance. It follows from what the Archelias were: they built a device to end humanoid life and keyed it to a humanoid hand. Whether that was oversight, or a last refusal to let the thing run without one of their own choosing to let it, is exactly the question Zworder could not answer. The correction requires the consent of the flawed.

It also puts real pressure on a machine empire pursuing the chain: the organics it needs are the ones the Ark will later judge, and keeping them alive is now instrumental rather than sentimental.

DECISION · SUPERSEDES G32

The chain unlocks at mid-game

Gate it on mid_game_years_passed >= 0 rather than a hard-coded year, so it respects whatever mid-game date the player configured at galaxy setup instead of fighting it. A fast-paced short game and a 1000-year marathon both get the chain at the point their own settings call mid-game.

DECISION · SUPERSEDES G33

AI empires can win the race too — and the restriction keeps the field small

I flagged this as tripling the AI work, and it does add real work. But the machine-empire restriction applies to them exactly as it does to the player, so the eligible field is not fifteen empires — it is however many machine empires the galaxy generated, typically none to three. The flooding problem the open version had solves itself.

It also makes those empires worth watching. A galaxy with two machine empires in it is a galaxy where the crisis has a face and a location long before it has a fleet, and where the diplomacy around them means something.

G34

Does an AI Ark-holder become a Nemesis crisis empire?

§17 leaned on Become the Crisis for the galaxy's response to a player holding the Ark. Whether vanilla AI ever takes that ascension path, and whether it can be scripted onto one, decides if an AI holder gets the same treatment or needs a parallel implementation.

If it needs a parallel path, that is the bulk of G33's real cost — not the precursor chain, which the AI already pursues for vanilla precursors.

G35

Galaxies with no machine empires at all

If neither the player nor any AI is a machine empire, nobody is eligible and the race content simply never appears — the Ark wakes on its timer and the campaign is the plain v0.1 crisis. That is a coherent outcome, not a bug, but it means a substantial body of work is invisible in many games.

Options: guarantee at least one machine empire at galaxy generation when the mod is active, accept the variance, or widen eligibility slightly — though widening costs the justification this whole section just established.

G36

What counts as "a human" in script terms?

Stellaris separates species archetype (biological, lithoid, machine) from portrait group (humanoid, mammalian, and the rest). "Humanoid" could mean the humanoid portrait group strictly, any organic pop, or a bespoke species flag the mod sets.

Strict portrait matching is the most faithful to the lore and the most likely to produce galaxies where nobody qualifies. Any-organic is the most playable. This is a fiction decision with a large gameplay footprint.

G37

Does the one who turns the key survive it?

A humanoid activating a device built to end humanoid life is the most charged moment in the chain, and it currently has no defined outcome. Consumed by the activation, elevated, or simply walks away — each reads as a different story about what the Ark is.

Mechanically it could cost the pop, the leader, or nothing. Narratively it is the scene the whole precursor chain has been walking toward, so it is worth deciding deliberately rather than defaulting to nothing.

§20

What the source actually says, and how far to stand from it

The wiki is blocked at this environment's proxy, so this came through search rather than the page itself — treat it as secondhand. Two details in it are worth more to the design than anything we have invented.

Two vessels, not one

I had these as a single ship. They are not. The Archelias built Shambleau — the Celestial Ark, the Star-Voyaging Ark, the World of Tranquility — an artificial planet that seeded the universe with Archelian genes and is the reason human species exist at all. The Ark of Destruction, nicknamed the White Comet, is the one with the Planet Catcher on it, and the one that kills.

So the tidy "seeding vessel repurposed as a cage" reading I offered is wrong, and the mod should not lean on it. What the sources give instead is better, because it is a property of the machine rather than a historical accident: as an Archelian ark, the Ark of Destruction reshapes itself to fit its user's needs when fully awakened. The cage is not a perversion of its design. It is the ark becoming what Gatlantis asked it to be.

The wielders were artificial, and that was not the builders' plan

The other detail worth having: in the source the Ark is not taken by its builders' descendants but by an artificial race created as slaves by another people, who rebelled against their creators and later went looking for it. So the pattern is already the one the mod arrived at independently — humanoids build it, an artificial people take it — and the machine-empire restriction turns out to have backing rather than needing a justification invented for it. My two previous attempts at that justification can both be retired.

DECISION · SUPERSEDES G36

The exemption is a flaw in the device's premise, not a fact about machines

Your point stands and it settles this: machines make war too, so "humanoid form causes violence" was never a sound diagnosis. The Archelias were wrong, and the Ark inherited their error. A machine empire is not exempt because it is peaceful — it is exempt because the machine is checking the wrong thing.

In script that argues for the broad reading: the activation key checks for a living organic pop rather than a strict portrait group, and the humanoid-form business is the Archelias' stated rationale rather than a literal condition. Faithful to the fiction, and it does not produce galaxies where nobody qualifies.

Mechanically it is clean: activation converts one of the empire's worlds into the first carried colony. The Ark never starts empty, the acquiring empire is bound to it from the first moment, and the boarding surface from §4 exists immediately — the empire's own world is the first door into its own fortress.

§21

The anatomy, and why the kill sequence climbs

The sources describe the Ark's structure precisely enough to place §4's three stages in physical space — which turns an abstract sequence into a route, and answers several things that were still open.

Four things this settles

01

The shell and the area weapon are one organ

The gas cloud is the shield and is the supergravity attack — it pulverises asteroids and strikes targets directly. So §15's simultaneous engagement gets sharper: the thing you must burn away is the thing hitting your line, and every point of shell you strip is a point of its offence you remove. One resource, both roles.

02

Golem is the builders' failsafe, not loot

It kills Gatlanteans — the wielders — instantly, and it sat directly beneath the throne for the empire's whole history. The notes had it as a captured superweapon; it is better than that. The Ark has always carried the means of its own wielders' destruction, and the wielder sat on top of it.

For the mod: stage 3 is not looting a weapon, it is reaching a switch that was installed before anyone got there. Which also means a player who takes the Ark has put that switch inside their own capital.

G39

The pilot is a person, and they made copies of him

The Ark could only be controlled by a human, its pilot was a named chancellor, and the vessel contained a reproduction device for manufacturing further copies of him. An artificial empire built a facility whose only purpose was producing the one human they could not operate without.

That is a far better mechanic than "own an organic pop". A named, maintainable pilot — losable, replaceable at cost — gives the two-key rule ongoing stakes instead of a one-time check. Open: leader, pop, or bespoke resource, and what happens between losing one and growing the next.

G40

There is a second defensive layer, and 10 million escorts

Inside the gas cloud sits a projected field of concentric light rings said to withstand hundreds of wave motion guns, and the Ark carries over ten million ships within its perimeter.

Both want deliberate handling rather than faithful transcription. A second layer could be a real second gate or could be cut as redundant with the shell; ten million ships is a number to abstract into a spawn schedule, never to instantiate — §4 already measured what six thousand does to a save.

Drift insurance, and why it is allowed to scan

A maintained counter can desynchronise. The reconciler does iterate ships — which is exactly what §4 forbids — so it runs only in the single system holding the Ark, and only on a monthly pulse. One system is not 3,287 fleets. The rule was never "never iterate"; it was "never iterate the galaxy every tick", and the difference is what makes a safety valve affordable.

Every equality assertion failed while every inequality passed, against the same variable in consecutive lines. That is what a variable that was never created looks like: absent reads as zero for > 0 but fails = 0.
