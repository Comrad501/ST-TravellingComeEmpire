STELLARIS 4.4.6 · PEGASUS · ARCHITECTURE MAP

Ark of Destruction

A travelling comet empire, and the six mechanisms it actually runs on

This maps the mod's subsystems onto the Clausewitz files that back them, so the dependency chains are visible before any of them are written. Two engine constraints force nearly every structural decision here; five unknowns are still open, and two of those block work that hasn't started yet. Everything below is drawn from the design notes — where the notes say unconfirmed, so does this page.

§1

Two constraints shape everything else

Neither is a preference. Both are engine limits, and both are already confirmed in the notes. Almost every unusual choice further down exists to route around one of them.

CONSTRAINT A · MOVEMENT

Planets cannot be relocated

There is no mechanism to move a galactic_object. So the Ark never carries a planet — it carries a colony that has been detached from one. Pops, jobs, districts and name travel; the planet object stays where it was and becomes a husk.

CONSTRAINT B · SCOPE

Situations cannot target a fleet

A Situation lives on a country scope and its target is a planet or empire. The base-game README is explicit about the target modifiers:

"Does not work on other scope types!"

This is why the Planet Catcher is load-bearing, not thematic. A captured colony is the only thing on the Ark a Situation can legally hook into.

§2

The system, both sides of it

The mod is not one machine. It is an Ark-side machine and a defender-side machine that meet in a shared script layer — and the fight the design wants only exists because the two sides read and write the same handful of flags and counters. Every subsystem below is named by its backing directory, because that is where the coupling actually lives.

§3

How a world gets carried

The instinct is to move the planet. The engine has no way to do that, and building anything on the assumption that it might is the single most expensive mistake available here. The capture is two ordinary operations instead, each with vanilla precedent, and neither one moves a planet.

The consequence worth noticing early: a carried colony has a normal invasion surface. That is not a side effect to work around — it is the boarding stage of the kill sequence, free, using the planetary invasion system as shipped. Every world the Ark takes is another door into it.

§4

Containment, without a per-tick scan

The containment field inverts the usual fight: defenders don't need to win, they need to survive in place; the Ark doesn't need to win, it needs to thin the emitters below a threshold and jump. Field strength is a function of how many inhibitor ships are alive nearby, so the mechanic lives or dies on how that number is obtained.

Counting it by iterating the ship list is the pattern that produces late-game slowdown, and the notes already record a save with 6,000+ ships. The count has to be maintained, not measured.

§5

The kill is a sequence, not a health bar

A boss you out-build is the wrong shape, and vanilla already says so: the Contingency and the Blokkat-Vester are both flatly invulnerable until a specific non-combat objective is met. The Ark follows the same rule — three gates, each opened by something other than damage.

§6

The stub seam

Two mechanisms — attaching a colony to the Ark, and stripping the comet shell — both have a Nomads implementation and a base-game one, and the DLC isn't owned. Rather than pick now, callers bind to four fixed names and the backing sits behind them.

The cost is one layer of indirection. What it buys is that the decision can be made later, or reversed, without touching a single call site — and that the mod stays runnable on the install that actually exists today.

§8

Four ways this fails silently

Each of these is recorded in the notes as a known trap. None of them produce an obvious error — they produce a mod that loads and then quietly misbehaves, which is far more expensive to find.

STATE LOSS

Swapping the ship_size

Treating "shell up" and "shell down" as two hulls means transferring modules, tier, damage, leaders and every attached colony on each transition. Layer a particle effect over one persistent entity instead — the ship object is never destroyed.

STUCK FOREVER

Omitting destroy_situation

A situation that reaches on_progress_complete or on_fail without calling destroy_situation = this stays live permanently. Nothing warns you; it just never goes away.

HARD ERROR

Missing desc keys

Every modifier block inside a monthly_progress script value needs its own localisation key. Skip one and the game errors rather than degrading — cheap to fix, easy to forget while iterating.

NO SOUND, NO WARNING

Encoding on music files

Both the .asset and the .txt need UTF-8 with BOM, and the track must be .ogg. Wrong encoding fails silently. Note the ambient-overwrite route wants .wav instead — a different pipeline entirely.

One more that isn't a trap so much as a prerequisite: EFCF is already installed, so this is a multi-mod setup. The DEBCF wiki's page on overwriting specific elements is worth reading before the first file is written, not after the first conflict.

§9

Build order

Sequenced so the two blocking unknowns are hit as late as possible, and so nothing gets built on top of an assumption that might not survive a prototype. Steps 1–6 need no unknown resolved.

  1. Mod skeleton

    descriptor.mod, directory tree, localisation stub, .gitignore. Loads and does nothing — which is the point.

  2. Ark hull and comet shell

    The ship_size, and the shell as a high-HP, high-regen defensive layer with an upkeep cost. Spawnable and lookable-at. No state swapping.

  3. Stub seam, empty

    The four names from §6 defined with correct signatures and no bodies. Locks the interface before anything calls it, so U4 and U5 stay genuinely deferred.

  4. Containment counting

    Tag-on-construction, three on_action hooks, one cached variable, one shared scripted_trigger. Performance-critical, so it goes in early and correct rather than late and retrofitted.

  5. Planet capture — Backing B

    Colossus-style strip plus colony transplant, behind ark_attach_colony. Produces a real carried colony, which unblocks both the situation layer and boarding.

  6. Situation layer

    Targeted at a carried colony per Constraint B. Bidirectional progress bar: contained at one end, escaped at the other. Fleet-level behaviour stays in fleet_event.

  7. Planet Catcher rendering

    Prototype U1 first. If sections can't swap live, fall back to a single mesh with all four cradles modelled and per-cradle visibility flags — uglier, certain to work, and it does not change anything above the seam.

    GATED ON U1 · U2

  8. Kill sequence

    Stages 2 and 3 can be built now — boarding is vanilla, and the Golem is a species-targeted one-use weapon. Stage 1 waits on your call about what replaces the Nomads cannon.

    GATED ON U5

  9. Music

    Playlist entry costs almost nothing and can ship whenever. The stage-triggered cue depends on U3 and is explicitly not worth blocking on.

§10

What the notes don't cover at all

Distinct from U1–U5. Those are questions the notes ask and can't yet answer; these are areas the notes never reach. Tier 1 changes what gets built, so it can't be deferred the way the unknowns can.

TIER 1

Architectural — answering these changes the build

4 gaps
G1

Is the Ark a crisis, a playable empire, or both?

The notes read both ways and never settle it. "Houses the empire's seat of government" and the player-side overload component point at playable. "Gives the defending side a real mid-game objective", "the Ark will prioritize killing it", and the Contingency/Blokkat framing point at an AI crisis.

This is the gap that sizes every other one. A crisis needs spawn conditions and AI behaviour and no economy at all; a playable empire needs an origin, a tech path, a build loop, and the whole of G2. They are not the same mod.

G2

The economy of an empire with no homeworld

One parenthetical about energy upkeep is the entire coverage. Unanswered: where income comes from; whether carried colonies run normal districts, buildings and jobs; whether the Ark acts as a mobile shipyard and starbase; what replaces the capital building chain, which requires a capital planet; how sprawl and admin cap work when you own no systems.

If G1 resolves to playable, this is roughly the larger half of the mod and it is currently unwritten. If it resolves to crisis, most of it evaporates.

G3

What happens when the Ark dies

If the seat of government is aboard, does the empire end instantly? What becomes of the four carried colonies — re-shattered, released as independents, or deleted with their pops? What if it dies while a situation is mid-progress and its target colony went down with the ship?

Partly a design question, partly a stuck-state risk: the situation layer's destroy_situation requirement needs someone to call it, and the obvious caller is the thing that just stopped existing.

G4

How the defender learns the kill sequence

There is a staged kill and a losing condition, but no event chain, research path, or advisor prompt that teaches anyone the cannon is the answer.

A stage-gated boss that never reveals the gate is indistinguishable from an unkillable one. The losing condition fires and the player never knew a counter existed. Vanilla teaches both the Contingency and Blokkat counters explicitly.

TIER 2

Specified too loosely to implement

4 gaps
G5

Nothing anywhere is quantified

No shell HP or regen rate. No containment radius R or ship-count threshold N. No duration for the exposed window after a shell strip, no capture duration, no Ark fleet power relative to a mid-game empire, no count of worlds at which the crisis is considered won.

Placeholder numbers would be enough. Without any, the design is describable but not testable — there is nothing to be right or wrong about yet.

G6

The Golem is one sentence

"Kills a target empire's population outright" leaves the scope open: all pops of a species galaxy-wide, one planet, or one empire's worlds? "Seized from the throne room" leaves the mechanism and the interface open too.

It is the reward for the entire boarding stage, so its scope sets how valuable stage 2 feels.

G7

The Anti Wave Motion Lattice is orphaned

Named once, flagged as needing a new component from scratch, then absent — not in the kill sequence, not in containment, not in the open questions.

Needs an explicit in-scope or cut. Right now it is neither, which is the state that quietly costs time later.

G8

AI behaviour, if G1 resolves to crisis

Zero coverage. When does the Ark jump, how does it choose targets, does it prefer weak empires or rich ones, how does it escalate over a campaign, how does it respond to difficulty and galaxy size?

The containment mechanic only produces interesting play if the Ark's side of it is making decisions worth countering.

TIER 3

Process — not design, but it will cost time

4 gaps
G9

Compatibility with EFCF

EFCF is installed and the notes already cite it as the working reference for locators — which means it touches the same file categories this mod will. There is no audit of whether they collide on ship_sizes, section_templates, or on_actions, and load order gets a single mention.

G10

The development and test loop

Nothing on how iteration actually happens: where error.log lives, the console commands to spawn the Ark, debugtooltip, a prepared test save.

This is the gap that gates the others. U1 and U2 can only be resolved by running the game, and I cannot run it — so the speed of your test loop is the speed of the whole project.

G11

No definition of done

No split between a first release and a complete one. With two blocking unknowns and a possibly-large economy subsystem, a deliberately small v0.1 is worth defining now.

G12

Save-game and version durability

No position on whether saves survive a mod update, what happens to an in-flight Ark when Stellaris patches, or whether the mod is ironman and achievement compatible.

WORTH DECIDING EARLY, NOT LATE

Intellectual property, if this ever goes to the Workshop

The concept is closely derived from Space Battleship Yamato — Gatlantis, Zemuria, the Ark of Destruction, wave motion technology. For a mod you run locally this is a non-issue. For a public Steam Workshop release it is real exposure: anime rightsholders do issue Workshop takedowns, and the risk is considerably higher if models, textures, or music are extracted from the games rather than made from scratch.

Raising it now because it is a decision about where the art comes from, and that gets expensive to reverse once assets are made. Original assets in the same visual language carry far less risk than ripped ones. This is your call to make — it just costs less to make it before the pipeline in §8 of the notes gets built out.

§11

G1, decided: an AI crisis first

DECISION · SUPERSEDES G1

v0.1 ships the Ark as an AI crisis. Playable is deferred, not dropped.

A playable displaced empire is the more interesting version and stays on the roadmap — but it is the harder build, and it is the one that most needs playtesting to justify. Crisis first means the mechanics get tested before the scope gets spent on them.

The saving is real but uneven. This is what actually moves:

LARGELY DEFERRED

G2 · the economy

Crises conventionally sidestep an economy: fleets arrive by event rather than being built, so no income model, no capital chain, no build UI. The largest gap in the list mostly stops mattering — for now.

PROMOTED TO CRITICAL

G8 · AI behaviour

It was the gap you could ignore while G1 was open. It is now the whole opposing player. Target selection, jump timing, escalation, scaling — and it still has zero coverage in the notes.

NOW MANDATORY

G4 · teaching the counter

Against an AI crisis the player is purely on the receiving end and has no other route to the rules. Without a reveal chain the kill sequence is unreachable by design.

UNCHANGED

Build steps 1–6

Hull, shell, stub seam, containment, capture, situation layer. All sit in the shared core, so none of them are wasted if the playable branch is built later.

The race the crisis actually is

A crisis is a pacing problem before it is a combat problem: the Ark collects on one clock and the defenders arm on another. Everything the AI layer has to decide is a question about where on this line something happens.

What choosing crisis newly opens

G13

Four slots, or indefinite collection?

§1 caps the Planet Catcher at roughly four worlds. §4 defines the losing condition as the Ark "collecting worlds indefinitely". Under a crisis reading these cannot both hold: a four-slot cage has a natural stopping point and therefore no escalation.

Four shapes to pick from: slots free as worlds are drained; four is only what renders while the tally is unbounded; the loss condition is time-based rather than count-based; or the Ark shatters worlds it cannot carry. Each implies a different escalation curve, so this is upstream of every number in G5.

G14

Spawn trigger and timing

Endgame-year like the vanilla crises, or mid-game? The notes want the cannon to be a mid-game objective, which pulls the Ark's arrival earlier than a standard crisis and lengthens the campaign it occupies.

Also unanswered: where it enters, whether the galaxy gets warning, and whether difficulty or galaxy size move the date.

G15

Target selection and jump policy

Which worlds does it want — highest pop, nearest, weakest defender, best deposits? And when does it choose to leave a system: on containment breaking, on a timer, on damage taken, on having filled a slot?

Jump policy is where containment either becomes interesting or becomes noise. If the Ark leaves the moment containment weakens, holding it is meaningful; if it leaves on a timer, the inhibitor ships are decoration.

G16

Escorts and reinforcement

Does the Ark travel alone or with a fleet, and if so, where do replacements come from? Crises conventionally spawn reinforcements by event on a schedule rather than building them, which keeps G2 deferred — but that schedule is itself an escalation curve nobody has drawn.

None of these block build steps 1–6, which is the point of having sequenced it that way. They block step 8 and the tuning pass, and G13 in particular is worth answering before any number in G5 gets picked, because it decides what those numbers are measuring.
